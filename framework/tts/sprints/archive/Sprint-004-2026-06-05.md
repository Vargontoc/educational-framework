# Sprint 004 - tts
# -----------------------------------------------

## Goal

Define the internal tone mapping configuration for `tts-educational`, so semantic tones from `api-educational` can later resolve to provider-specific Chatterbox and XTTS v2 parameters without changing the backend contract.

## Tasks

- [ ] Define supported semantic tones: `calm`, `joyful`, `enthusiastic`, `serious`, `neutral`.
- [ ] Create a versioned internal tone mapping definition for Chatterbox.
- [ ] Create a versioned internal tone mapping definition for XTTS v2.
- [ ] Ensure provider-native fields remain internal and are not exposed in `docs/contracts/api/openapi_tts.json`.
- [ ] Add a stable mapping version identifier, such as `toneMappingVersion` or `synthesisProfileVersion`.
- [ ] Add mapping resolution tests for every supported tone and provider.
- [ ] Add controlled error tests for unknown tone and unknown provider.
- [ ] Verify mapping tests pass without Chatterbox, Coqui, GPU, or Docker Compose.

## Risks

- Provider-specific parameters leak into the backend contract.
- Tone behavior changes without cache invalidation if mapping version is not included later in cache keys.
- Tone names drift from the agent/backend tone enum.
- Chatterbox and XTTS v2 may produce different emotional results for the same semantic tone.

## Agent Instruction

- Implement only the internal tone mapping definition and mapping resolution tests.
- Do not implement provider adapters (Chatterbox, Coqui/XTTS).
- Do not call Chatterbox or Coqui.
- Do not implement real synthesis.
- Do not implement provider fallback logic.
- Do not implement WAV/PCM to MP3 conversion.
- Do not add cache endpoints or cache invalidation behavior.
- Do not modify `framework/infrastructure/docker-compose.yml` or `framework/infrastructure/docker-compose.prod.yml`.
- Do not modify backend or frontend source files.
- Do not add public API endpoints or diagnostic endpoints.
- Keep Chatterbox parameters such as `exaggeration`, `cfg_weight`, `temperature`, and `audio_prompt` internal.
- Keep XTTS v2 parameters such as `speaker_wav` and `speed` internal.

## Notes

This sprint defines the translation table only. Future provider adapters will consume this mapping when real Chatterbox and Coqui/XTTS calls are implemented. No public API changes.
