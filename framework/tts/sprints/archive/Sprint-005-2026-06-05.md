## Risks

- API structure grows before real provider needs are known
- Provider-specific details leak into route handlers
- Adapter stubs are mistaken for production-ready integration

## Agent Instruction

- Implement only FastAPI structure, router organization, provider adapter stubs, and configuration loading
- Do NOT call Chatterbox or Coqui/XTTS containers
- Do NOT implement real synthesis
- Do NOT implement provider fallback logic
- Do NOT add cache endpoints or cache invalidation behavior
- Do NOT modify `framework/infrastructure/docker-compose.yml` or `framework/infrastructure/docker-compose.prod.yml`
- Do NOT modify backend or frontend source files
- Do NOT change the public contract in `docs/contracts/api/openapi_tts.json`
- Stub adapters must return controlled values — `501` for synthesize endpoint, empty bytes for audio
- Health endpoint must not require provider containers
- Status endpoint must expose converter availability without leaking provider-native parameters

## Notes

This sprint prepares the FastAPI structure for later provider integration features. Real Chatterbox and Coqui/XTTS calls will be implemented separately.
